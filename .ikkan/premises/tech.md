# dragon の技術の構成と制約

## 構成

- pnpm の workspace で、`apps/*` と `packages/*` を持つ (`pnpm-workspace.yaml`)。
- TypeScript の ESM で書く (`package.json` の `"type": "module"`、`tsconfig.json`)。
- package は tsup で build する。build は最初にブロックと図の種類の置き場の dir から一覧を書き出す (`packages/dragon/scripts/build-blocks.mjs`、#3345)。依存は字 (`@fontsource-variable/noto-sans-jp`、`@fontsource-variable/jetbrains-mono`) と書き出しの部品 (`gifenc`、`mediabunny`、`subset-font`) だけ (`packages/dragon/package.json`)。
- 描画は `packages/dragon` の中に持つ。`@cardenelabs/cdl` への依存は #2983 で外した (#2982)。
- 見本帳は Vite と React 19 で作り、経路は依存を足さずに `history` で持つ (`apps/playground-spa/src/site/routes.ts`)。Tailwind 4 の plugin は Vite の設定に残るが、今の頁は使っていない (`apps/playground-spa/package.json`、`apps/playground-spa/vite.config.ts`)。
- 見本帳の公開の build は、読み込んでよい場所を CSP の meta で絞る (`apps/playground-spa/vite-csp.ts`)。
- 見本帳は、概要の頁と編集画面の最初の見本のほかの見本の記法と、部品の図の記法を、それぞれ1つの後から読む塊に分け、最初の画面を描いた後に裏で読む (`apps/playground-spa/src/site/later.ts`、#3246)。裏で読むのは見本の記法だけで、見本が使う読み方と絵柄集 Tabler の表は、見本を並べる所 (編集画面とカタログの頁) が見本の塊 (`LATER_EXAMPLES`) を待つ時に読む (`apps/playground-spa/src/examples.ts`、#3505)。
- 見本帳の使い方の頁とカタログの頁も後から読む塊に分け、同じ仕組みで読む (`apps/playground-spa/src/site/pages.tsx`、#3280)。頁の塊が読めなかった時だけ、頁を1度自動で読み直す (#3288)。
- 最初に読む言葉の表 (`apps/playground-spa/src/text.ts`) は、最初の画面と、後から読む塊が届く前と届かない時に出す字だけを持つ。カタログの頁だけが使う字 (図の種類の説明を含む) はカタログの頁の塊に入る `apps/playground-spa/src/catalog/text.ts` が、編集画面の棚の記法の早見の説明は記法の見出しが後から読む `apps/playground-spa/src/editor/syntax-text.ts` が持つ (#3565)。英語の画面の字と最初の画面の見本3枚の英語の記法は英語の塊 (`apps/playground-spa/src/english.ts`) が持ち、頁は英語で開く時と英語に替える時に英語の塊が届くまで英語で描かない。編集画面の棚の部品と記法の早見の行の雛形 (`apps/playground-spa/src/editor/shelf-items.ts`) は、棚が後から読む (#3646)。
- 字は Noto Sans JP と JetBrains Mono を同梱し、`@cardenelabs/dragon/fonts` の入口から読む (`packages/dragon/src/load-fonts.ts`)。見本帳は組み立て結果の字だけを切り出した 1 つの字の `file` を読み、組み立ての時に分割された字の面の範囲からその字を外す。切り出した字に無い字は分割された字の `file` から読む (`apps/playground-spa/src/site/font-sheets.ts`、`apps/playground-spa/vite-site-font.ts`、`apps/playground-spa/scripts/site-fonts.mjs`、#3296)。見本帳は字の CSS を最初の CSS に入れず、初めて開く端末は最初の画面を描いた後に読み、前に読んだ端末は描く前に読む (`apps/playground-spa/src/site/fonts.ts`、#3292)。
- 既定の入口 `@cardenelabs/dragon` は全ての図の種類の部品と全てのブロックの読み方を持つ。軽い入口 `@cardenelabs/dragon/light` はコアブロックと、時系列図と構成図の個別ブロックの読み方を持ち、`chart`、`cycle`、`er`、`flow`、`git`、`lineup`、`mind`、`pipe`、`state`、`time`、`tree`、`try`、`venn` の描く部品と、その種類だけの個別ブロックの読み方を後から読む。`loadFor` は書いた図の種類の描く部品と書いた図が使うブロックだけを、`loadKind` は種類の描く部品とその種類の全てのブロックを読む。見本帳は軽い入口だけを読み、図を描く所と書く所は種類の塊 (`loadKind`) を待ち、見本の塊は見本が使う物を `loadFor` で読む (`packages/dragon/src/light.ts`、`packages/dragon/src/blocks/used.ts`、#3248、#3349)。原本の形の検査 (`packages/dragon/src/schemas/validate-diagram.js`) は既定の入口だけが初めから持ち、軽い入口は原本の JSON を渡した `loadFor` と、`loadKind` と `loadValidator` で後から読む。`parseNotation` で記法から読んだ図は印を持ち、描く時に検査を省いて字のまま SVG と頁に入る path と URL だけを確かめる (`packages/dragon/src/parsed.ts`、`packages/dragon/src/version.ts`、#3400)。`mountDiagram` が試す図を置く時と読み手が押した時に写した図も、元の図が印を持てば印を引き継ぐ (`packages/dragon/src/player.ts`、#3416)。足したブロックの定義を読む処理も後から読む塊で、見本帳は定義の行を持つ記法 (`definesBlocks`) だけ、その塊を待ってから読む (`apps/playground-spa/src/site/kinds.ts`、#3399、#3407)。
- script の 1 行の入口は `dist/cdn/dragon.js` に build し、頁は ES module として読む。軽い入口と同じく書いた図の種類の描く部品と使うブロックだけを後から読み、図の字の CSS を jsDelivr から読む `<link>` を頁に 1 度だけ足し、頁の `<pre class="dragon">` の塊を図に置き換える。`dragon embed` は頁の 1 行を、全ての図の種類の部品を束ねた `dist/offline.global.js` の中身に置き換え、字は埋めない (`packages/dragon/src/script.ts`、`packages/dragon/src/script-offline.ts`、`packages/dragon/src/page-blocks.ts`、`packages/dragon/src/export/embed.ts`、#3343)。頁が読む `dist/cdn/dragon.js` は何も import しない案内役で、URL の `@cardenelabs/dragon@<版>` を自分の版に書き換えた場所から本体 `dist/cdn/dragon-main.js` を読み、本体と塊を案内役と同じ版に揃える。版を含まない置き場では隣の本体を読む (`packages/dragon/src/script-loader.ts`、#3375)。
- 頁で描く入口 `@cardenelabs/dragon` は Node の組み込みの module を読まず、原本の file を移す `migrateFile` は Node でだけ動く入口 `@cardenelabs/dragon/node` に置く (`packages/dragon/src/node.ts`、#3206)。

## 検査

- `pnpm test` は repo の根で vitest を回す (`package.json`、`vitest.config.ts`)。
- vitest は回す前に、`packages/dragon` の `dist` が `src` より古くないかを見る (`test-support/global-setup.ts`)。
- `pnpm run verify` は型、build、lint、`pnpm test` の順に回す (`package.json`)。
- 課題ごとには、変えた所に関係する検査だけを `pnpm test:related` で回す (`scripts/test-related.mjs`)。検査の file が import をたどって読む file と、表 (`test-support/related-table.json`) が名指す素材から選び、どの規則にも当たらない file を変えた時は選ばずに断る。一式は版を出す前の配る前の関門で 1 回だけ回す (#3381)。1 回の実行が 5 分の上限で止まった時は、止める段 (`test-support/run-limit.ts`) が `DRAGON_UNFINISHED_OUT` の file に書いた終わっていない file だけを次の実行で回し、終わっていない file が減らなくなったら止める (#3386)。止める段は書き先を読んだ後に環境変数から外し、検査が起こす vitest が同じ書き先へ書かないようにする (#3388)。
- 検査は 1 件とその前後処理を 10 秒、1 回の実行を 5 分で止め、止めた検査の名前を出す (`test-support/limits.ts`、`test-support/test-limit-guard.ts`、`test-support/run-limit.ts`)。検査が自分で書いた上限もこれより長くは待たない (#3381)。
- 1 件の中で画面の大きさや見本の組を順に回す検査は、組ごとの件 (`describe.for`) に分け、件の名前は変えない。外した検査と、その守りを担う検査は `docs/removed-tests.md` に残す (#3381)。検査を選ぶ命令 (`scripts/test-related.mjs`) を起こす検査も入力ごとの件に分け、件ごとに命令を子のプロセスで1回だけ起こす (#3602)。
- 全ての見本を描く検査と分類の見本を順に開く検査は見本ごとの件に、書き出しを起こす検査は 1 件 1 回の書き出しに分け、書き出す図と形式とコマの数をその件が確かめる最小にする。上限を 4 秒に下げて (`DRAGON_TEST_LIMIT_MS=4000`) 同時に 1 つで回しても通る大きさに保つ。npm に出す file の一覧は 1 回の実行の準備の段で 1 度だけ `npm pack --dry-run` で出し (`test-support/pack-setup.ts`)、一覧を読む検査の file を回す時だけ起こす。命令の元の code を検査の中で読み直す file は、元の code が読む部品を file を読む段で先に読み、変換の手間を検査の外に出す (#3410)。
- カタログの部品の頁の部品ごとの件は、部品ごとに頁を 1 度だけ開いて使い回す (`catalog-parts.test.ts` の `partPage`)。読むだけの件を先に回し、頁を移る件と言語を替える件は部品の頁と日本語に戻して終わり、編集画面へ移る件を最後に置く (#3432)。
- 書き出した頁の帯と釦の件は、最初に要った件が `oauth.json` を HTML に 1 度だけ書き出し、残りの件は同じ HTML を使う (`export.test.ts` の `oauthHtml`)。幅ごとの件に分け、件ごとにその幅の頁を 1 度だけ読み込む。書き出した頁を開く道具 (`export-support.ts` の `withPage`) は動きを嫌う設定を頁を開く前に渡し、開いた後に `emulateMedia` で当てて読み直さない。字の file の件は見本ごとの件に分け、字の file を読ませる道具は file の Chromium を使う (#3421)。
- `packages/dragon/test/` の検査は、Chromium を自分で起こさず、file で 1 つの Chromium (`page-needs.ts` の `fileChromium`) を使う。初めて要った件が起こし、頁は文脈ごとに開いて閉じ、Chromium は後処理で閉じず file の process の終わりに止まる。書き出しの命令を起こす件は 1 件で命令を 1 回まで起こし、全ての見本の字を選ぶ件は字を符号の順に分けた組ごとの件にする (#3424)。書き出しが起こす Chromium も、`export-support.ts` を読む file では `shared-chromium.ts` が差し替えて同じ 1 つを借り、書き出しが閉じる時は書き出しが開いた文脈だけを閉じる。`export.test.ts` と `export-language.test.ts` は書き出しの命令を子の Node のプロセスで起こさず、組み上がった命令を同じ process の中で走らせる (`runCliInProcess`、#3599)。軽い入口の検査で見本や種類を回す4つの検査は見本ごとの件に分け、子の Node のプロセスを起こさず、件ごとに読み込みの記録を消して (`vi.resetModules`) 軽い入口を読み直す (`light-entry.test.ts` の `freshLight`、#3580)。jsdom で動く file の書き出しは、書き出しの thread (`export-thread.ts`) で回し、thread の中で 1 つの Chromium を借りる (`shared-chromium.ts` の `lendThreadChromium`)。thread を作り Chromium を起こす段は、書き出す件の前の準備 (`beforeAll` の `warmThread`) で済ませる (#3602)。
- 見本帳の検査は頁を開かない。頁は 1 回の実行の準備の段で 1 度だけ build し (`site-setup.ts`)、build の結果の中身を読む (`playground-support.ts` の `builtDir`)。見た目は本人の目で見て決める (#3381、#3585)。
- script の 1 行の入口の検査は、build した `dist/cdn` を `http://localhost/` に置いた Chromium で開き、外への通信を止めて、読んだ塊と足した `<link>` を数える。どの塊がどの種類の描く部品を持つかは、塊の source map が名指す `kinds/<種類>/layout.ts` で見分ける (`packages/dragon/test/script-entry.test.ts`、#3343)。修正版を出した直後の jsDelivr は、版の範囲の場所に入口だけを置き、ほかの file を 404 にした置き場で真似る (#3375)。
- 字の重なる図を作れないため、重なりを知らせる流れは、重なりを探す所 (`findOverlaps`) を包んで重なりを 1 件足して確かめる。書き出しの命令は `vi.mock` で包み、見本帳は検査だけの build の設定で包む (`packages/dragon/test/paired-overlap.ts`、`apps/playground-spa/src/lib/overlap-build-support.ts`、#3197)。
- 描いた図の崩れの検査は、見本に今ある崩れを数えた一覧 (`packages/dragon/test/fixtures/layout-breaks.json`) と見比べ、一覧に無い崩れで落とす。一覧は `node scripts/layout-breaks-record.mjs` で書き直す。見本帳の図 (ブロックの `gallery` の `.dragon`) は一覧を持たず、崩れを1件も出さないことを確かめる (`packages/dragon/test/layout-check.test.ts` の `gallery-warns-nothing`、#3607)。プラグインの skill を入れた Claude の評価 (`claude plugin eval`) は回すたびに費用がかかるので検査の中で回さず、`node scripts/plugin-eval-record.mjs` が回した結果をケースの指紋と一緒に `plugins/dragon/evals/record.json` に残し、検査 (`packages/dragon/test/plugin-eval.test.ts`) は記録を読む (#3484)。評価の囲いは GitHub にも npm にも届かないので、記録の script は fork の代わりの写しの repo と、GitHub へ通信せず受けた引数を書き残す偽の `gh` を作り (`scripts/plugin-eval-stand-in.mjs`)、評価を下ごしらえ付き (`--scaffold`) で回す (#3508)。写しのrepoの外で呼んだ偽の `gh` は一時のdir (`TMPDIR`) の下の `dragon-eval-gh/` に引数と本文を書き、`gh issue create` にはIssueのURLを返す (#3513)。記録を書いた後に記録のscriptは、各実行で保存した `.dragon` の最後の段と `dragon check --layout` が崩れを知らせた段を囲いの外でPNGに書き出し、ケースごと・実行ごとに並べた1枚の頁 (PNGをdata URIで埋めたHTML) を写しのdirの `gallery.html` に書いて、置き場を出力の最後の行に出す (`scripts/plugin-eval-gallery.mjs`、#3519)。評価の結果を報告するAIは、この頁をArtifactで公開してリンクを渡す。
- 頁の中で動く値は `pnpm test:mutation:values` で 1 つずつ書き換えて検査を回し、受入条件が全部 `今を守る` の課題に要る壊して測った結果の表は、その結果の file から `pnpm test:mutation:table <変異の一覧> <結果の file> --step <数>` で作る (`scripts/mutate-values.mjs`)。
- 依存の中身が公開されている物と一致するかを `pnpm verify:deps` が確かめ、network を使う (`packages/dragon/scripts/verify-dep-integrity.mjs`)。
- 依存の既知の脆弱性は `scripts/check-dependency-vulnerabilities.sh` が `osv-scanner` で見る。
- 外の脆弱性の一覧に問い合わせる本物の走査は、版を出す前の一式の最後に 1 回だけ走る。検査の中では代わりの道具で命令の判定だけを見る (#3498)。
- 版を上げた時に、`packages/dragon/package.json` の版が前提の配り方の節と `CHANGELOG.md` の見出しに書かれているかを確かめる (`packages/dragon/test/release-records.test.ts`)。英語の `CHANGELOG.md` と日本語の `CHANGELOG.ja.md` は 0.35.0 以降の版を同じ見出しと同じ課題番号で持ち、片方へ書き忘れると同じ検査が落ちる (#3321)。
- `.github/workflows` は持たない (`git ls-files`)。

## 制約

- node は 18 以上 (`packages/dragon/package.json` の `engines`)。
- package の任意の peer 依存は、mp4 や GIF への書き出しで使う `playwright-core` (`packages/dragon/package.json` の `peerDependenciesMeta`)。
