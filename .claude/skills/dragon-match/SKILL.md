# dragon-match — 正解の図と作った図を一覧で確かめる

## 位置付け

本 skill は正解の頁と作った図を 1 図ずつ測る。

測った後は expected.png、actual.png、checklist.md をすぐ user に見せる。

図を直すかどうかと直す内容は、呼ぶ側が表と user の指摘から決める。

## 起動 trigger

使い方は 2 つある。

### 新しい図を作る時

dragon-diagram から呼ぶ。

正解の頁は docs/design/proposal/<図の名>.html に置く。

合わせる一覧は docs/design/proposal/<図の名>.checklist.json に置く。

1 回測って撮って見せ、直すたびにまた 1 回測って撮って見せる。

回数の上限は置かない。

### 見本帳の図を見本へ合わせる時

正解の頁は docs/design/proposal/static/ の見本を使う。

着手時に図ごとの合わせる一覧を user と握る。

一覧は .context/match/<図の名>/checklist.json に置く。

1 回測って撮って見せ、直すたびにまた 1 回測って撮って見せる。

回数の上限は置かない。

### 共通の終わり方

一覧の全ての升が「合う」になった時に終わる。

「測れない」または「cdl 待ち」の升が残る時は、残った内容を添えて user に見せる。

その状態で終わるかは user が決める。

一覧に無い字体、数 px、cdl で描けない所は、user が絵で指摘した時だけ直す。

## 前提

- 起動 dir は dragon repo root とする。
- 正解の頁は手元の静的 HTML とする。
- 作った図は静的 HTML または見本帳の図とする。
- 意匠は順序を持つ一覧として受け取り、測定と撮影で順序を変えない。

## 段取り

段取りは 2 段だけである。

### 1. 受け取る

正解の頁、作った図、意匠の一覧、合わせる一覧の path を受け取る。

正解の頁を指す CSS selector が無ければ body を使う。

作った図が見本帳にある時は、見本帳の base URL、頁の名前、図の名前、意匠の英名を受け取る。

頁の名前は charts や flows のような catalog の頁名とする。

図の名前は一覧の札に出る字か、札の data-item-id とする。

正解の頁を作ることと、その頁と一覧を正解として user と握ることは呼ぶ側が持つ。

### 2. 1 回測って撮って見せる

丸ごとの設定を .context/match/<図の名>/match.json に書く。

最上位の checklist に合わせる一覧の path を書く。

noteRoot は省略でき、省略時は docs/design とする。

検査では fixture の note の置き場を noteRoot に書く。

    {
      "checklist": "docs/design/proposal/荷物の流れ.checklist.json",
      "noteRoot": "docs/design",
      "comparisons": [
        {
          "label": "図面",
          "expected": {
            "type": "html",
            "path": "docs/design/proposal/荷物の流れ.html",
            "selector": ".fig",
            "palette": "blueprint"
          },
          "actual": {
            "type": "catalog",
            "baseUrl": "<見本帳の base URL>",
            "page": "animation",
            "name": "荷物の流れ",
            "palette": "blueprint"
          }
        }
      ]
    }

両側とも html と catalog のどちらでもよい。

静的 HTML は path と任意の selector を持つ。

静的 HTML は、色を判定する意匠だけ任意の palette を持つ。

見本帳は baseUrl、page、name と任意の palette を持つ。

palette に site-colours を書くか palette を省いた時は、図の色味の選ぶ欄で「画面の色」を選ぶ。

その時は svg[data-cdl-stage] に data-cdl-palette が無いことを確かめてから測る。

表と撮った絵の札は「画面の色」にし、parts/ の file 名には site-colours を使う。

画面の色には note.md が無いため、色の項目は「測れない」にする。

各側には任意で region と ignoreTexts を書ける。

region はその側の図の root 座標で、中心が範囲内にある字・箱・線だけを測り、撮影も同じ範囲で切り取る。

ignoreTexts は測定に含めない字の配列である。

見せるたびに N を 1 増やし、同じ出力 dir に次の 2 command を 1 回ずつ走らせる。

    node .claude/skills/dragon-match/scripts/measure.mjs \
      .context/match/<図の名>/match.json \
      -o .context/match/<図の名>/run-<N>

    node .claude/skills/dragon-match/scripts/shoot.mjs \
      .context/match/<図の名>/match.json \
      -o .context/match/<図の名>/run-<N>

--cdl-wait は使わない。

渡された時は「cdl 待ちは合わせる一覧の項目の cdl待ち に書く形へ移った」と出して非 0 で止まる。

チャットへ expected.png、actual.png、checklist.md の表を貼る。

意匠が多く、2 枚の全体像では読みにくい時は parts/ の意匠ごとの組を 1 組ずつ見せる。

## 合わせる一覧

一覧は JSON で、version と items を持つ。

    {
      "version": 1,
      "items": [
        { "名": "工程が揃う", "種類": "字", "字": ["受付", "仕分け", "配達"] },
        { "名": "工程が左から順", "種類": "並び", "向き": "横", "字": ["受付", "仕分け", "配達"] },
        { "名": "受付から仕分け", "種類": "つながり", "から": "受付", "へ": "仕分け" },
        { "名": "受付の地", "種類": "色", "字": "受付", "部分": "地", "役": ["箱の面", "行の面"] },
        {
          "名": "配達の枠",
          "種類": "色",
          "字": "配達",
          "部分": "枠",
          "役": "枠",
          "cdl待ち": {
            "理由": "枠を意匠別に切り替える欄が無い",
            "cdl の課題": "cardene777/cdl#1226"
          }
        }
      ]
    }

version が数値の 1 でなければ、一覧を読まずに止まる。

### 判定

| 種類 | 合う条件 |
|---|---|
| 字 | 指定した全ての字が図にある |
| 並び | 字の中心が指定順に並ぶ。横は左から右、縦は上から下 |
| つながり | 線の始点が「から」の字の箱に、終点が「へ」の字の箱に接する線が 1 本以上ある |
| 色 | 字の箱の地、枠、または字の色が、意匠の note.md にある役の値と一致する |
| 崩れ | 箱どうしの重なり、字のはみ出し、図の枠の外が全て 0 件 |

「崩れ」は一覧に書かなくても必ず最後の 1 行に入る。

つながりで端が箱の中にある時は、距離 0 として接している。

箱の外にある時は、端から箱までのユークリッド距離が root 座標で 8 以下なら接している。

8 は、線端の丸めと矢じりのために箱の縁へ置く小さな隙間を許しながら、隣の箱へ誤接続しないための値である。

この判定により、線が箱の下に描かれて端が箱へ隠れる形も合うと判定できる。

線だけの図形の端に塗りのある小さな図形が接する時は、その塗り図形の輪郭上で線端の外向きに最も出る点を線端とみなす。

接触は root 座標で 1 以下、元の線端から最遠点までが 24 以下の図形だけを対象にする。

1 は線端と矢じりの境の丸めだけを許す値で、24 は正解頁の幅 19・高さ 17 の矢じりを含みながら、箱や札を矢じりと誤認しない上限である。

線が marker-start または marker-end を持つ時は、marker の中身の輪郭点を viewBox から markerWidth・markerHeight の枠へ写し、refX・refY を線端へ合わせる。

markerUnits が strokeWidth なら枠を線の太さ倍し、userSpaceOnUse なら書かれた大きさのまま使う。

orient が auto ならその端の線の向き、auto-start-reverse なら始点だけその逆向き、角度なら指定角で印を回す。

線の終点では終端接線の向き、始点では始端接線を反転した向きを、線端の外向きとする。

写して回した印の輪郭点のうち、線端から点への向きと線端の外向きとの root 座標での内積が最も大きい点を線端とみなす。

最大の内積が 0 以下なら、印は線端から外へ出ていないため元の線端を保つ。

この marker の印は、線端に接する別図形の矢じりと同じ扱いにする。

SVG 自身を測る時と、HTML の中にある SVG を測る時で同じ規則を使う。

字の中心を含む箱、または枠か地を持つ祖先が見つからない時だけ、字と横の範囲が重なり、
字の上端か下端から箱の縁までが root 座標で 8 以下の箱を結び付ける。

8 は、箱の上の名前との間 3 と箱の下の値との間 7 を拾いながら、隣の箱まで届かない値である。

最も近い箱を選び、同じ距離なら面積の大きい箱を選ぶ。

同じ距離かつ同じ最大面積の箱が 2 つ以上なら字の箱を決めない。

同じ位置と大きさの図形は 1 つの箱にまとめ、地は塗りのある図形、枠は線のある図形から読む。

字が図に無くて並び、つながり、色を判定できない時は「合わない」とし、無い字を残す。

cdl待ち を持つ項目は、元の判定が合わない時だけ「cdl 待ち」とする。

「cdl 待ち」の升には理由と cdl の課題を残す。

元の判定が合う時は「合う」とする。

### 色の値

色は <noteRoot>/<意匠の英名>/note.md の ## 値 節だけから読む。

色の項目の `役` は字 1 つまたは空でない字の配列で書く。

配列では先頭から順に note.md にある役を探し、最初に見つかった役の値を使う。

どの役も note.md に無い時は、字 1 つの時と同じく「測れない」とする。

その節にある表のうち、値の欄が backtick で囲んだ 1 つの #rrggbb で始まり、その後ろが空か「。」で始まる説明である行だけを読む。

値の欄に色が 2 つ以上ある行と、色で始まらない行は読まない。

同じ役の名が読める行に 2 回以上ある時は、読んだ色が全て同じならその色を使う。

色が違う時だけ止まり、違う色とそれぞれの note.md の行番号を出す。

意匠の英名が無い時、または note.md が無い時は、その意匠の色の項目を「測れない」とする。

kinari と celadon は note.md を持たないため、この扱いになる。

正解の側も同じ一覧で判定する。

正解の側の色は、正解の source に palette がある時だけ判定する。

正解の側で合わない項目は、checklist.md の先頭へ「一覧の誤り」として出す。

「一覧の誤り」があれば、図を直す前に user と一覧を握り直す。

## 結果の置き場

1 回分を .context/match/<図の名>/run-<N>/ に置く。

| file | 中身 |
|---|---|
| result.json | version: 1、意匠ごと・項目ごとの判定、合わない時の作った図の値、崩れの中身、正解の側の判定 |
| checklist.md | 一覧の誤り、項目を行・意匠を列にした表、合わない・測れない・cdl 待ちの件数 |
| expected.png | 正解の絵 |
| actual.png | 作った図の絵 |
| parts/expected-<英名>.png | 意匠ごとの正解の絵 |
| parts/actual-<英名>.png | 意匠ごとの作った図の絵 |

result.json は別 process と次の回の main session が読むため、最上位の version を必ず残す。

## 部品の分け方

一覧の判定は .claude/skills/dragon-match/scripts/checklist.mjs に置く。

この部品は測った値の plain object、一覧、note.md の中身から作った値の表だけを受け取る。

browser と file system は使わない。

measure.mjs は図を browser で開いて測り、checklist.mjs に渡し、file を書く。

shoot.mjs と parts/ の意匠ごとの組は撮影だけを担う。

## 統合先 skill

| 関係 | skill | 何を渡すか |
|---|---|---|
| 上流 | dragon-diagram | 正解の頁の path、一覧の path、作った図の名前、意匠の一覧 |
| 上流 | 見本帳の図を見本へ合わせる作業 | 静的な見本、一覧の path、見本帳の頁と図の名前、意匠の一覧 |

## 責務外

- 正解の頁と合わせる一覧を作り、user と握ることは呼ぶ側が持つ。
- 図を直すことは呼ぶ側が持つ。
- 候補を並べて選んでもらうことは dragon-propose が持つ。
- 全件の検査と PR の準備は呼ぶ側が 1 回行う。
- 一覧に無い違いを自動で探して合否へ加えることはしない。
