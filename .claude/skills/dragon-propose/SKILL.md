# dragon-propose — 案を並べて選んでもらう

## 位置付け

図を変える判断は、文章では決まらない。
「数が小さい」 も「間伸びしてる」 も、絵を並べて初めて何が違うか分かる。

この repo の skill は 3 本あるが、どれも候補を複数並べる段を持たない。
そのため案を見せたい時は毎回その場で頁を組むことになり、作り方も拡大の仕方も毎回変わる。

本 skill がその段を 1 箇所に持つ。
呼ぶ側は候補を考えて絵を撮るところまでを持ち、並べ方と拡大と回答の受け取りは本 skill が持つ。

## 起動 trigger

user 明示起動、または上流 skill からの呼び出し。

```
/dragon-propose 端の数の寸法
/dragon-propose            引数なしなら何を決めたいか 1 問だけ聞く
```

引数は何を決めたいかを表す短い語。
`.context/propose/<topic>/` の名前になる。

## 前提

- 起動 dir は dragon repo root
- 見本帳の dev server が動いている (`pnpm dev` → `http://localhost:4323`)
- 作業 branch に居る (既定 branch では書けない)

## 段取り

6 段ある。

### 1. 何を決めるかを 1 文にする

決めたいことを 1 文で書く。
「端の数と走る玉の寸法をどこまで大きくするか」 のように、答えが寸法 / 配色 / 配置のどれかに
落ちる形にする。

ここが「図をよくする」 のような形のままだと、候補が互いに比べられないものになる。

### 2. 候補を 2 から 4 つ作る

**変える軸を 1 つに絞る**。
寸法の案なら寸法だけを動かし、配色は 4 案とも同じにする。
2 つ以上動かすと、どちらが効いたのか選ぶ側に判らない。

候補には **いまの形を必ず 1 つ入れる**。
変えない案が無いと、変えた側どうしの比較になり、そもそも変えるべきかが決まらない。

4 つを超えない。
5 つ以上は人が比べきれないので、先に `/grilling` か `/discuss` で絞る。

### 3. 絵を撮る

候補ごとに **2 種類** 撮る。

| 何を | 大きさ | なぜ |
|---|---|---|
| 図ぜんたい | 実寸 (見本帳と同じ倍率) | 全体の釣り合いが見える。 候補どうしの差はここに出る |
| 決めたい所 | 4 倍 | 細部 (数と印の隙間 / 玉が印に入っていないか) は実寸では判定できない |

撮り方は呼ぶ側が持つ。
Playwright で見本帳を開き、候補ごとに値を差し替えて撮る script を `.context/scratch/` に書く。

置き場は `.context/propose/<topic>/img/`。

### 4. 頁を組む

候補の一覧を JSON で書き、組み立てる。

```bash
node .claude/skills/dragon-propose/scripts/build-sheet.mjs \
  .context/propose/<topic>/候補.json -o .context/propose/<topic>/sheet.html
```

JSON の形は § 候補の一覧。

**足りない形は script が止める**。
候補が 1 件 / 絵が 0 枚 / 推す案が 0 件や 2 件以上 / 絵の file が無い、のいずれも error で落ちる。
黙って出すと、見せたつもりで見せていない頁ができる。

### 5. 公開して聞く

頁と絵を Artifact で公開する。

```
Artifact(file_path: ".context/propose/<topic>/sheet.html",
         root: ".context/propose/<topic>",
         files: { "img/....png": "img/....png", ... },
         icon: "...", description: "...")
```

公開したら AskUserQuestion で答えを受け取る。
選択肢は候補と 1 対 1 にし、推す案を先頭に置いて `(Recommended)` を付ける。

**頁の中に回答欄を作らない**。
答えは AskUserQuestion で受け取る = 頁は見るためのもので、2 箇所に答える場所を作らない。

### 6. 選ばれた案を残す

`.context/propose/<topic>/chosen.json` に書く。

```json
{
  "選んだ": "c",
  "日付": "2026-10-02",
  "却下": [{ "id": "d", "理由": "玉が描く側の見込みを超える" }],
  "但し書き": "案のままでは図が間伸びするので、余白は据え置く"
}
```

但し書きは、選ばれた案をそのまま実装しない場合にだけ書く。
**書かずに値を変えない** = 選んでもらった形と違うものが出ると、次から選ぶ意味が無くなる。

ここまでが本 skill の範囲で、実装は呼ぶ側に戻す。

## 候補の一覧 (JSON)

```json
{
  "題": "端の数と走る玉の寸法",
  "小見出し": "dragon 見本帳 / クラス図",
  "ねらい": "何を決めたいかを 1 から 2 文",
  "問い": "どの案で通しますか。",
  "脚注": "絵をどう撮ったか",
  "表": {
    "題": "4 案を見比べる",
    "見出し": ["案", "数の大きさ", "玉の半径"],
    "行": [
      { "値": ["A いま", "19", "9"] },
      { "値": ["C はっきり", "26", "12"], "推奨": true }
    ]
  },
  "候補": [
    {
      "id": "a",
      "名前": "A いま",
      "説明": "1 文。 何が良くて何が気になるか",
      "絵": [{ "path": "img/zen-a.png", "題": "図ぜんたい (実寸)" }]
    }
  ],
  "覚書": [{ "題": "見出し", "本文": "決める前に知っておくこと" }]
}
```

欄の意味。

| 欄 | 要る | 中身 |
|---|---|---|
| `題` | 要る | 頁の題。 Artifact の名前にもなるので 2 から 4 語 |
| `問い` | 要る | 答えてほしいこと 1 文 |
| `候補` | 要る | 2 から 4 件。 1 件だけ `推奨: true` |
| `候補[].絵` | 要る | 1 枚以上。 `path` は JSON からの相対 |
| `表` | 任意 | 候補をまたいで見比べる値。 **札の外に置く** = 枠の中に書くと案をまたいで比べられない |
| `覚書` | 任意 | 選ぶ前に知っておく制約 |

**良い点と気になる点は `説明` に 1 文で書く**。
札の中に長く書くと、案をまたいで読み比べられない。
比べる値は `表` に出す。

## 完成形の定義

成果物は 2 つ。

1 つは候補を並べた頁 `.context/propose/<topic>/sheet.html`。
`scripts/build-sheet.mjs` が候補の一覧 (JSON) と絵から組み立て、そのまま Artifact に公開できる。
明暗の両方を持ち、携帯の幅でも横に溢れない。

もう 1 つは選ばれた案の記録 `.context/propose/<topic>/chosen.json`。
どの案が選ばれ、どの案をなぜ却下し、そのまま実装しない場合は何が違うかを持つ。

## 統合先 skill

| 関係 | skill | 何を渡すか |
|---|---|---|
| 上流 | `/dragon-diagram` | 新しい図の案を 2 から 4 つ (題材が同じで組み方が違うもの) |
| 上流 | `/dragon-design` | 見た目の案 (配色 / 寸法 / 配置) |
| 上流 | `/dragon-redraw` | 今の絵と狙いの絵 (段取り 4 がこれを呼ぶ) |
| 併用 | `artifact-design` | 頁の契約 |
| 下流 | 無し | 選ばれた案を返して終わる。 実装は呼んだ側へ戻す |

## 責務外

- 候補の考案 (何を変えた案にするか) は呼ぶ側が持つ。 本 skill が案を作り始めると `/dragon-diagram` と重なる
- 絵の撮影 (dev server の操作と Playwright) は呼ぶ側が持つ。 何を変えた案かは呼ぶ側しか知らない
- 選んだ後の実装は呼ぶ側に戻す
- 記法を足すこと / 例文の題材を決めることは `/dragon-diagram` が持つ
- 決めた内容を repo に残すことは `/dragon-design` (`docs/design/notation/`) と `/dragon-redraw` (`docs/design/drawing/`) が持つ
- 文章の赤入れは `/redline` が持つ。 本 skill が相手にするのは絵だけ

## 落とし穴

- **候補に「いまの形」 を入れ忘れない**。 変えた案どうしの比較になり、そもそも変えるべきかが決まらない
- **1 つの候補で 2 つ以上の軸を動かさない**。 どちらが効いたか選ぶ側に判らない
- **実寸だけ / 拡大だけで見せない**。 実寸は釣り合いを、拡大は細部を見るためのもので、片方では判定できない
- **頁に回答欄を作らない**。 答えは AskUserQuestion で受け取る
- **選ばれた案を黙って変えない**。 変えるなら `chosen.json` の但し書きに書き、変えた理由を伝える
- 画面から取った SVG は `width: ... !important` を持つことがある。 絵は PNG で撮る
- 絵は `root` と `files` で一緒に公開する。 頁に埋め込むと原寸で見た時に粗くなる
