# dragon-extend — 図の種類と部品を足す

## 位置付け

説明に合う図が無い時に、新しい図の種類か部品を足すまでを1か所に持つ。
足す物を決める判定、見本で選んでもらう段、ikkan の線で足す段、取り込んだ後に版を聞く段の4段を、この順に回す。

列の図 (#3239) を足した時、記法の語、原本の形、検査の関数、読む部品、書き戻す部品、時刻の表、置き方、描き方、値の表、見本、見本帳の部品、編集画面の棚、既存の検査の一覧まで十数か所に登録が要った。
足す手順がどこにも無く、頁の大きさの上限と見本の説明の決まりは全部の検査を回すまで見つからなかった。
登録先は `references/registry.md` に一覧で持ち、過去に足した取り込みで変えた file が一覧から漏れると `packages/dragon/test/extend-skill.test.ts` が落ちる。

## 起動の時

2つの入口がある。

| 入口 | 起動のしかた |
|---|---|
| 図解を書く AI が描けない所に当たった | AI がこの skill の判定を回し、足す案を示して、課題を立てるかを AskUserQuestion で本人に聞く。立てると答えた時だけ起票する |
| 本人の依頼 | `/dragon-extend <描きたい動き>` か「〇〇を描ける図を足したい」 |

bitsumi の図解を書く `diagram-writer` は、今の記法で描けない説明に当たった時にここへ来る。
引数が無い時は、何を描きたいかを1問だけ聞く。

起動の dir は dragon の repo root で、描画の package を build 済み (`pnpm build:packages`) にしておく。

## 1. 足すかを判定する

説明したい動きを1文にし、次の順に確かめる。
先の段で描けたら、そこで止めて後の段へ進まない。

| 順 | 確かめること | 描けた時 |
|---|---|---|
| 1 | 今の記法で描けるか | 足さずに、描いた記法を返して終わる |
| 2 | 今の図の種類に部品を足せば描けるか | 部品を1つ足す |
| 3 | 新しい図の種類が要るか | 図の種類を1つ足す |

部品で描けるかを先に確かめる。
図の種類を足すと、見本帳の分類、編集画面の棚、全ての部品の図、書き方の文書まで増え、覚える語も頁の重さも増えるため。

今の記法と部品は `packages/dragon/README.md` の記法の節と `apps/playground-spa/src/catalog/parts.ts` の一覧で読む。
今の記法で書いてみて、描けない所を「どの動きが、なぜ今の語で言えないか」の1文で残す。

記法の語は、今の語で言えない時だけ足す。
足す語は英語の動詞1語にする。
語が増えるほど覚えきれなくなり、一度出した語は書いた原本が増えるほど替えにくくなるため。
新しい語が今の図の種類の名札とぶつからないかも、ここで確かめる。

1つの課題で足すのは1つだけにする。
判定で2つ以上が要ると分かった時は、足す物ごとに分けて、先に要る物から順に足す。

## 2. 見本で選ぶ

足す物の見た目と語を、本人が見本で選ぶ。
見本を見ずに決めると、足した後に見た目が他の図と揃わないと分かり、作り直しになる。

| 足す物 | 見せ方 |
|---|---|
| 新しい図の種類 | 今の dragon では描けないため、HTML と CSS で動く試作を3案作り、1枚の頁に並べて見せる |
| 部品 | 今の図の種類に描けるため、`dragon-propose` で書き出しの絵を並べて見せる |
| 新しい語 | 候補の英語の動詞を2つか3つ、同じ動きをその語で書いた記法の見本と並べて見せる |

動く試作を3案作る時は、置き場を `.context/extend/<要点>/` にし、3案とも同じ説明の同じ動きを描く。
変える軸は見た目の型 (並べ方、動き方) に絞り、配色と字の大きさは `docs/design/base/` の決まりに揃える。
並べた頁は Artifact で公開し、答えは AskUserQuestion で受ける。

見本は日本語と英語の見本をそろえて見せる。
見本帳も編集画面も2つの言葉を持ち、英語で字の幅が変わると置き方が崩れることがあるため。

選んだ案と却下した案とその理由は、次の段で立てる課題の決める段 (step 2) に残す。

## 3. ikkan の線で足す

選んだ案を ikkan の課題にし、ikkan の線で足す。
step の進め方と関門は ikkan が持ち、ここには写さない。

### 課題を立てる

`/ikkan:ikkan-triage` の手順で、足す物1つにつき1つの課題を立てる。
背景には判定の1文と選んだ見本を、期待する形には見本帳と編集画面に載った後の形を書く。

完了条件に一式を入れない。
完了条件は足す物の検査の名前で書き、全ての検査を回す一式は版を出す前の `deployable.sh` で1度だけ回す。
一式は全部の図の種類を回すため、種類が増えるほど遅くなる。

### 登録先を触る

`references/registry.md` の表の行を上から順に触る。
図の種類を足す時は「図の種類を足す時」の表を、部品を足す時は「部品を足す時」の表を使う。
表の行は過去の取り込みで実際に変えた file から作ってあり、触らない行がある時はなぜ要らないかを PR の本文に書く。

書き方の文書は使い方の頁とREADMEと手引きの3つを、記法と同じPRで直す。
使い方の頁は `apps/playground-spa/src/docs/content.ts`、READMEは `README.md` と `packages/dragon/README.md`、手引きは `packages/dragon/examples/quick-start.md` と英語の `packages/dragon/examples/quick-start.en.md` である。
後の課題に回すと、描けるのに書き方が載っていない版が出る。

### 語を替える時

1.0までは語を替えてよい。
替えた時は、前の語で書いた原本を `readDiagram` (`packages/dragon/src/version.ts`) が読み替える形を同じ PR で足し、`CHANGELOG.md` に替えた語と読み替えを書く。
次の版は minor の番号を上げる。
1.0を出した後に語を替えるかは、ここでは決めない。

### 必ず足す検査

足すたびに次の2つを確かめる。

| 検査 | 確かめること |
|---|---|
| `renderers-read-values-from-one-table` (`packages/dragon/test/look.test.ts`) | 新しい描き方の file が色と字の大きさを直に書かず、`packages/dragon/src/look/values.ts` の値の表から読む。新しい描き方の file はこの検査が見る file に入る |
| ほかの種類では名札として読む検査 | 新しい語を、ほかの図の種類では箱の名札として読む。列の図では `notation-keeps-lineup-words-plain-outside-lineup` (`packages/dragon/test/lineup-diagram.test.ts`) が持ち、同じ形の検査を足す物の検査の file に置く |

値の表の検査は、見た目が他の図と揃わない形を止める。
名札の検査は、新しい語がほかの図の種類の原本を読めなくする形を止める。

### 回す検査

検査を回す前に `pnpm build:packages` を打つ。
見本帳の検査は build した package を読むため、打たないと前の描き方で回る。

回すのは足す物の検査と、`references/registry.md` の表が挙げる既存の検査に絞る。

## 4. 取り込んだ後に版を出すかを聞く

課題を取り込んだら、版を出すかを本人に聞く。
AskUserQuestion で「今出す」と「ほかの追加と束ねて後で出す」を並べる。
足すたびに版を出すと、使う側の更新が増えるため、束ねる案も必ず出す。

版を出すと答えた時は、版を切る課題を立てるところまでを行う。
npm と見本帳へ出すことは本人が言い出した時だけ行い、この skill は出さない。
出す前に `/ikkan:ikkan-deploy` の `deployable.sh` で一式を回す。

## 完成形の定義

足した図の種類か部品が、ikkan の課題ごとに1つの PR として既定の branch に入り、次のことが揃った状態を完成とする。

- 記法で書け、読んだ原本を書き戻すと同じ記法に戻る
- 見本帳の図の頁と部品の頁に、日本語と英語の見本で載る
- 編集画面の棚から書き始められる
- 使い方の頁とREADMEと手引きに書き方が載る
- `CHANGELOG.md` の Unreleased に足した物が載る

## 統合先 skill

| 関係 | skill | 渡す物 |
|---|---|---|
| 上流 | bitsumi の `diagram-writer` か本人の依頼 | 今の記法で描けない説明と、描きたい動き |
| 下流 | `dragon-propose` | 部品の見た目の案と撮った絵 |
| 下流 | ikkan の各 step の skill (`ikkan-triage`、`ikkan-discuss`、`ikkan-spec`、`ikkan-tdd`、`ikkan-impl`、`ikkan-land`) | 足す物ごとの課題 |

## 責務外

- 図解の本文と段の出典を書くことは bitsumi の `diagram-writer` が持つ
- 部品の案の頁を組んで答えを受けることは `dragon-propose` が持つ
- step の進め方と関門は ikkan が持ち、この skill は写さない
- 版を切って npm と見本帳に出すことは版を切る課題が持つ
- 描く部品と検査の関数を図の種類ごとに後から読むことは #3248 が持つ。見本と部品の図の記法は #3246 で後から読む塊に分けた

## 落とし穴

- 部品で描けるかを確かめずに図の種類を足さない。種類を足すと覚える語と頁の重さが一度に増える
- 1つの課題で2つ以上を足さない。どの変更が何を壊したかが分からなくなる
- 見本を見せずに見た目を決めない。見た目の良し悪しは本人の目で決める
- 見本の file の最初の注釈の行に作業の番号を書かない。見本帳はその行を説明に出し、`example-descriptions-carry-no-issue-number` (`packages/dragon/test/examples.test.ts`) が落ちる
- 原本の形を直したら検査の関数を書き出し直す。手順は `references/registry.md` の原本の形の行が持つ
