# infra-demo

クラウドの構成を階層で示す図。 箱を列と行に置き、繋がりを線で結ぶ。

## 決めたこと

箱の幅は種類と中身で決まり、280 と 320 の 2 値を取る。
`er-demo` のように 1 値で揃えない = ER 図は表を並べる図なので幅が揃う方が読みやすいが、
構成図は種類の違う箱を並べるため、中身に合わせて伸びる方が字が詰まらない。

箱の高さは 116 と 172 の 2 値。 小見出しと説明を書いた箱が 172、名前だけの箱が 116。
cdl 0.20.0 で名前だけの箱は 54 まで縮み、段が近づいて説明が隣の線に重なった (`#1498`)。
中身を足せば箱が中身ぶんの高さに戻る。

角の丸みは 18。 6 件のうち 5 件で測れ、1 件は角を持たない形 (円筒) のため測れない。
`er-demo` の 16 と違うのは engine が種別ごとに当てる値で、この図で決めた値ではない。

枠の太さは静かな箱が 1.75、今光っている箱が 2.5。 `er-demo` と同じ。
繋がりの線は 2.25 で、箱の枠より太く、光っている箱の枠より細い。
線が箱より前に出ず、かつ静かな箱の枠に埋もれない位置に置いた。

**同じ節から出る線は重ねたまま残す**。
`App` から出る `SQL` と `GET/SET` は起点から 84 だけ同じ道を走り、そこで上下に分かれる。
太い幹から枝が出る形として読め、読み手は共有した起点から分岐を辿れる。
分けると図幅が広がるだけで得るものがない (cdl `#211` の判断)。

段は 5 つ。 段が進むごとに繋がりが 1 本ずつ増え、箱は最初の段から出したままにする。
`er-demo` と同じ組み立てで、構成図でも「何が何に繋がるか」 を 1 本ずつ読ませる。

色は箱の面に `--cdl-node-fill`、枠と字に種別ごとの `--cdl-tone-*` (`accent` / `info` /
`teal` / `warning`) を当てる。 線は `--cdl-tone-accent`、今の段は `--cdl-now`。
台は `--cdl-canvas-bg`。

動きの時間は engine が要素に持たせている値をそのまま使う。
箱が `opacity 120ms` と `transform 200ms`、線が `stroke 280ms` と `stroke-width 280ms`。

## 見送ったこと

箱の幅を `er-demo` と同じ 1 値に揃える案。
図全体が整うが、`CloudFront` と `User` では名前の長さが倍近く違い、揃えると短い方に
余白が溜まるか長い方で字が詰まる。

同じ節から出る線をずらす案。
線の本数が目で数えられるようになるが、`#211` の判断を覆すことになり、同じ形を持つ
他の図 280 件の見た目も変わる。 得られるのは本数の見分けだけで、図幅への影響が大きい。

`topo-demo` のように囲みで括る案。
どこまでが 1 つの区画かは判りやすくなるが、列と行で階層を作る基本形が別の図になる。
囲みの意匠はこの形を決めた上に乗せる方が、差分として書ける。

角の丸みを `er-demo` の 16 に揃える案。
2 つの図で同じ値になるが、丸みは engine が種別ごとに当てる値で、意匠帳の側から
指定する口を持たない。 揃えるなら engine を直す別の作業になる。
