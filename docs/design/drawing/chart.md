# 値の図の描き方

`type: chart` の 9 つの形 (`stat` / `waffle` / `pie` / `radial` / `gauge` / `stacked` /
`bar` / `line` / `slope`) が共有する判断を残す。

対象は札の大きさ = 図が絵を描く矩形で、器 (`viewBox`) そのものは隣の `stage.md` が持つ。

## 測った数

見本帳を実際の画面で開いて測った。
2 組ある。

### 札に対する中身の割合 (#2708 で足した)

札 (`node-body`) の矩形に対して、その中で描かれた線と字の外接が占める割合になる。
図の題は札の外に出るので数えない。

| 図 | 形 | 横 (前 → 後) | 縦 (前 → 後) |
|---|---|---|---|
| 今月の解約件数 | `stat` | 22% → 36% | 43% → 57% |
| 荷物の大きさ | `waffle` | 57% → 79% | 86% → 86% |
| 荷物の状態 | `pie` | 59% → 78% | 81% → 81% |
| 機能ごとの利用率 | `radial` | 63% → 78% | 85% → 85% |
| 配達の結果 | `stacked` | 92% → 92% | 39% → 64% |
| 定時に届いた割合 | `gauge` | 79% (変えていない) | 85% |
| 営業所ごとの取扱数 | `bar` | 85% (変えていない) | 86% |
| 月ごとの配達数 | `line` | 85% (変えていない) | 79% |
| 営業所ごとの定時率 | `slope` | 92% (変えていない) | 87% |

**札を詰めただけで割合が上がったのではない**。
画面は器の横幅に合わせて倍率を決めるため、札が細くなると倍率が上がり絵そのものが大きくなる。
実測では弧が 461 から 554、格子が 422 から 549、数値が 160 から 241 に伸びた (画面の実寸)。

### 文字の広がり (`drawing-measure.mjs`)

| 図 | 広がり (前 → 後) | 切れた名前 | 読める字 |
|---|---|---|---|
| 今月の解約件数 | 10% → 16% | 0 → 0 | 11 |
| 荷物の大きさ | 17% → 23% | 0 → 0 | 28 |
| 機能ごとの利用率 | 19% → 23% | 0 → 0 | 45 |
| 荷物の状態 | 34% → 44% | 0 → 0 | 31 |
| 配達の結果 | 42% → 44% | 0 → 0 | 58 |

切れた名前は前も後も 0 件で、この変更の成果ではない。
広がりは器に対する一番外側の文字の位置なので、札の中で絵が大きくなった分をそのままは映さない。
直ったかの判定には前節の割合を使う。

## 決めたこと

### 1. 札の横幅を形ごとに決める

`packages/dragon/src/compile/value-chart.ts` の `札の大きさ` が 9 つの形の `w` と `h` を持つ。

縦が中身の大きさを決める形は、横をいくら広げても絵が大きくならない。
描画側の弧は `外半径 = min(使える高さ / 2, 弧に使える幅 / 2)` で決まり、格子は行数で高さを
使い切る。
横を一律 640 にしていた間、余った分は左右の余白になるだけだった。

| 形 | 前 | 後 |
|---|---|---|
| `stat` | 640x320 | 384x240 |
| `waffle` | 640x320 | 464x320 |
| `pie` | 640x320 | 480x320 |
| `radial` | 640x320 | 512x320 |
| `stacked` | 640x368 | 640x224 |

`gauge` (79%) と `bar` (85%) と `line` (85%) と `slope` (92%) は変えない。
既に使い切っているので、狭めても余白が減らず数だけが上がる。

### 2. 縦を使わない形を高くしない

`stacked` は帯 2 本と一覧だけで縦に伸びない。
368 だと中身 143 に対して縦の 39% しか埋まらず、下に空きが残っていた。

### 3. 大きさは 16 の倍数で渡す

描画側が大きさを 16 の倍数へ切り上げるため、外れた値を渡すと下端が格子から外れ、
全図で位置の警告が出る。
棒と折れ線の 368 は 360 を切り上げた値になる。

### 4. 数が実物とずれたら落ちる検査を置く

`apps/playground-spa/tests/chart-card-fill.spec.ts` が実際の画面で 9 つの形を描き、
札に対する中身の割合の下限を見る。

下限は「今の実測より少し下」 ではなく「直す前より上」 に置く。
直す前を跨がない下限は、札の大きさを元に戻しても落ちない = 何も守らない。
5 つの形を 640 に戻すと 6 件の違反を出して落ちることを実測した。

### 5. 組立て API の側は `itemWidth` で揃える

描画側の `chart()` preset は横幅の既定を 640 のまま持つ。
見本帳の円は組立て API でも書いてあるので、そちらに `itemWidth: 480` を渡して記法と揃える。
ずれたら `catalog-source-parity` が「描いた図が違う」 で落ちる。

## 退けた案

### 札はそのままで中身を広げる

`stat` の数値の級は描画側が 112 で止める。
弧と格子は高さで決まる。
どちらも見本帳の側からは触れないため、この案は描画側の変更になる。
先に札の側で済む分を確定させ、数値の級は別に切り出した (次節)。

### `stat` を正方形にする

`384x288` を試した時点で縦の使用率は 47% にしかならなかった。
数値が 112 で止まる以上、高くするほど上下が空く。
高さを 240 まで詰めると 57% になり、これが数値を 112 のまま保てる最小の高さになる
(`240 - 余白 96 - 名前 20 - 間 12 = 112`)。

### 形ごとの数を書かず、中身から自動で決める

見本帳の側は描画側が何を何 px で描くかを知らない。
弧の半径も格子の行数も描画側の中で決まるため、組み立ての時点では中身の幅を引けない。
実物から測って書き、ずれたら落ちる検査を置く形にした。
