# 器 (枠と欄) の描き方

図種によらず全ての図が共有する器の判断を残す。
枠 (`viewBox`) をどう決めるか、欄 (`svg`) を出すかどうかの 2 つが対象になる。

図種ごとの描き方は隣の `<図種>.md` が持つ。

3 件とも根は 1 つで、**見えないものを器の大きさに数えない** ことになる。
別々に見つかったが、同じ原則の別の現れ方だった。

## 測った数

見本帳を実際の画面で開き、描かれた線と字の外接を画面の座標系で測った。
塗りも線も持たない矩形は数えない。

| 何を | 直す前 | 直した後 |
|---|---|---|
| 右の余白が左より広い図 | 117 枚 / 117 枚 | 4 枚 |
| 左右の差 (中央値、枠の幅に対する百分率) | 12.0 | 0.0 |
| 左右の差 (最大) | 27.3 | 1.1 |
| 絵が枠を占める割合 (中央値) | 35% | 40% |
| 図の欄に見えるものが 1 つも無い図 | 17 枚 / 486 枚 | 0 枚 |

残る 4 枚 (`shape-auditor` / `shape-lawyer` / `shape-notary` / `shape-regulator`) の 1.1 は名前の文字の幅の違いによるもので、器の判断ではない。

## 決めたこと

### 1. 見えない帯を枠に入れない

枠に入れる帯を **絵を出す帯だけ** にした。
入れる時は左右と上下の両方を渡す。
節も同じく両端を渡す。

帯が枠いっぱいに絵を出すのは `contain` (点線の囲い) と `lifeline` (縦の点線) の 2 つだけ。
それ以外の帯が描くのは当たりを取るための `fill="none" stroke="none"` の矩形で、見えない。

帯の名前は別に `lane-label` として枠に入っているので、帯の箱としては要らない。

実装は [cdl#920](https://github.com/cardene777/cdl/pull/920)。

### 2. 絵の基準が見た目の中心とずれる時は、広がりの差の半分だけ寄せる

絵は節の中心を基準に組むが、部品が左右へ出る量は同じではない。
買い物かごはハンドルの握りが左へ 122 出るのに、一番右まで来る影は 80 しか出ない。
基準をそのまま絵の中心として扱うと、描いたものが 21 単位ぶん左へ寄る。

寄せる量は **絵が使っている値から導く**。
差を直に書くと、部品の大きさを変えた時に中心の計算だけが古くなる。

```ts
const 左へ出る = HANDLE_GRIP_X + HANDLE_GRIP_R;
const 右へ出る = CART_SHADOW_RX;
const cx = r.cx + ((左へ出る - 右へ出る) / 2) * s;
```

`* s` は絵の倍率。
寄せる量は絵と同じ空間にあるので倍率が要る。
掛け忘れは箱の大きさが既定値の時だけ正しく見えるため、箱の大きさを 2 通り以上で確かめる検査でしか捕まらない。

実装は [cdl#922](https://github.com/cardene777/cdl/pull/922)。

### 3. 描くものが 1 つも無い図は欄を出さない

図の欄が出すのは帯と線と節の 3 つだけで、残りは見えない矢頭になる。
3 つとも無い図は面だけを取る。

```ts
function 描くものがある(laid) {
  if (laid.edges.length > 0) return true;
  if (laid.nodes.some((n) => isRenderedNode(n))) return true;
  return laid.lanes.some((l) => l.contain === true || l.lifeline === true || Boolean(l.label));
}
```

あわせて、**書いた時点で隠れると決まっている節を枠に入れない** ようにした。
判定は `isRenderedNode` が既に持っているので、枠の側で書き直さずそれを引く。
節そのものと、外接矩形として渡ってきた分の両方を外す。
片方だけ外しても、もう片方が枠を作る。

`{signal}` を含む条件は今までどおり枠に入れる。
外すと段を進めるたびに枠が動く。

実装は [cdl#924](https://github.com/cardene777/cdl/pull/924)。

## 退けた案

| 案 | 退けた理由 |
|---|---|
| 帯を枠に入れず、節だけで枠を決める | 囲い (`contain`) を描く帯が枠からはみ出す。 見える帯と見えない帯を分ける必要がある |
| 絵の中心合わせに `fitArt` を使う | 縦の中心も合わせるため、買い物かごが持つ縦の寄せ (`cy + 10`) を打ち消す |
| 寄せる量を数値で直に書く | 部品の大きさを変えた時に中心の計算だけが古くなる |
| 空の欄の高さだけ小さく固定する | 空の枠線が残り、なぜ何も無いのかが読む人に伝わらない |
| 「数値の札だけの図」 と書いた案内を出す | engine が文言を持つことになり、言語ごとの訳が要る |
| 見本帳の側で空の欄を畳む | 同じ判定を使う側ごとに書くことになる |
| 段によって出たり消えたりする節も枠から外す | 段を進めるたびに枠が動く |

## 測り方の落とし穴

数が画面と食い違った時は、画面ではなく測り方を疑う。
以下は全てその形で、いずれも直したのは測り方のほうだった。

**節の地を「絵ではない」 として外した**。
絵記号の図では地そのものが絵なので、占める割合が 83〜90% と出て、絵が 2 割しかない画面と真逆になった。
塗りと線を実際に見る形に直した。

**幅と高さの両方が 0 より大きい部品だけを数えた**。
水平な線は高さが 0 で返るため、順序図の横線が 1 本も入らず、この図だけ偏っているように見えた。
どちらか一方が 0 より大きければ数える形に直した。

**一番大きい `svg` を拾った**。
欄が消えた瞬間に札の部品を掴んで「直った」 と返す。
目印 (`svg[data-cdl-stage]`) で欄そのものを引く形に直した。

**節の中の `<text>` を空白でつないでから、書いた文字を含むかを見た**。
engine は幅に収まらない文字を 2 つの `<text>` に分けて描くため、つなぐ時に空白を挟むと元の文字列に戻らない。

```
書いた値   予定を持つ日
描かれた   <text>予定を</text><text>持つ日</text>
つないだ   "予定を 持つ日"   ← 空白が入り、含まれないと判定した
```

これで折り返しただけの名前を「末尾が切れている」 と数え、予定表の図を直す作業に入りかけた。
空白を全て落としてから比べる形に直すと、切れている名前は 0 件になる。

**この直しは 1 つの物差しだけでは確かめられない**。
0 件は「直った」 とも「測れていない」 とも読めるため、engine が別に持つ物差し (末尾が `…` で終わる名前を数える) と突き合わせた。
そちらも 486 枚で 0 件を返し、2 つが同じ答えになったことで 0 件を根拠にできる。
