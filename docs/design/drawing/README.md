# 描き方の決定記録

engine が線をどう引き、箱をどこに置き、枠をどう決めるかの判断を 1 件ずつ残す場所。

隣の `../notation/` とは軸が違う。
あちらは図 1 つの見た目を焼き付けて残す場所で、ここは描き方そのものの判断を残す。

## 置き方

図種ごとに 1 file 置く。

```
docs/design/drawing/<図種>.md
```

`<図種>` は記法の `type:` か `shape:` の値を使う (`mind` / `tree` / `quadrant` 等)。
catalog の図の id ではない。
同じ描き方を使う図が複数あるので、判断は図種に属する。

## 書く欄

4 つ書く。

| 欄 | 中身 |
|---|---|
| 測った数 | 文字の広がりを直す前と後で |
| 決めたこと | 何をどう描くか |
| 退けた案 | 出したが選ばなかった案と、その理由 |
| まだできないこと | 実装していない項目と、その行き先 (Issue 番号) |

退けた案を書くのは、次に同じ議論をやり直さないため。

## 数の出し方

```bash
node apps/playground-spa/scripts/drawing-measure.mjs --group charts --samples 14 --interval 400
```

文字が枠にどれだけ広がっているかを測る。
図形ではなく文字を測るのは、どの図も枠いっぱいにカードの地を敷くため。
`node-body` の矩形が 1 つで枠の 65% を占めるので、図形を数えると全図が 9 割で並んで差が消える。

低いこと自体は欠陥ではない。
計器の図は数字 1 つしか置かないので 1% になる。
数は相手を探す入口で、判定そのものではない。

## 色を書く時

16 進の値を書かない。
書くとそこだけ古い値が残る。

変数の名前 (`--d-accent` / `--d-text-secondary` 等) で書けば、指す先が変わっても記述は正しいまま。
値そのものは `apps/playground-spa/src/styles/globals.css` を見る。

これは `../notation/README.md` § 色は変数の名前で書く と同じ決まりで、同じ理由による。
