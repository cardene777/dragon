# 描き方の決定記録

engine が線をどう引き、箱をどこに置き、枠をどう決めるかの判断を 1 件ずつ残す場所。

隣の `../notation/` とは軸が違う。
あちらは図 1 つの見た目を焼き付けて残す場所で、ここは描き方そのものの判断を残す。

## 置き方

図種ごとに 1 file 置く。

```
docs/design/drawing/<図種>.md
```

`<図種>` は記法の `type:` か `shape:` の値を使う (`mind` / `tree` / `quadrant` 等)。
catalog の図の id ではない。
同じ描き方を使う図が複数あるので、判断は図種に属する。

## 書く欄

4 つ書く。

| 欄 | 中身 |
|---|---|
| 測った数 | 3 つの数 (文字の広がり / 切れた名前 / 読める字) を直す前と後で |
| 決めたこと | 何をどう描くか |
| 退けた案 | 出したが選ばなかった案と、その理由 |
| まだできないこと | 実装していない項目と、その行き先 (Issue 番号) |

退けた案を書くのは、次に同じ議論をやり直さないため。

## 数の出し方

```bash
node apps/playground-spa/scripts/drawing-measure.mjs --group charts --samples 14 --interval 400
```

1 回の読み取りから 3 つの数が出る。

| 数 | 何を映すか |
|---|---|
| 文字の広がり | 図が枠を使い切っているか |
| 切れた名前 | 末尾が `…` で終わる名前の数 |
| 読める字 | 省略の印と空白を除いた字の数 |

図形ではなく文字を測るのは、どの図も枠いっぱいにカードの地を敷くため。
`node-body` の矩形が 1 つで枠の 65% を占めるので、図形を数えると全図が 9 割で並んで差が消える。

3 つ要るのは、広がりが一番外側の文字で決まるため。
軸の名前と区画の名前は元から枠の端にあるので、内側の名前が読めるようになっても外周は動かない。
描き方を 3 件直した回は 3 枚のうち 2 枚で広がりが 1 ポイントも動かず、残る 1 枚も 1 ポイント
しか動かなかった。
同じ 3 枚で切れた名前は 5 件 → 3 件 と 1 件 → 0 件 に減っている (#2669 で実測)。

広がりで相手を探し、切れた名前と読める字で直ったかを見る。

測るのは画面の座標系になる。
`getBBox()` は祖先の変換を見ないため、箱ごとに `<g transform="translate(...)">` で位置を
与える図では離れた名前がすべて同じ値を返し、重ねると 1 つ分に潰れる (#2665 で実測)。
別の物差しを足す時も同じ形を踏むので、座標系を先に決める。

広がりが低いこと自体は欠陥ではない。
計器の図は数字 1 つしか置かないので 1% になる。
数は相手を探す入口で、判定そのものではない。

切れた名前が 0 件であることも、名前が短いだけの図では既定の状態になる。
0 件を成果として書くなら、直す前も 0 件だったかを併記する。

## 色を書く時

16 進の値を書かない。
書くとそこだけ古い値が残る。

変数の名前 (`--d-accent` / `--d-text-secondary` 等) で書けば、指す先が変わっても記述は正しいまま。
値そのものは `apps/playground-spa/src/styles/globals.css` を見る。

これは `../notation/README.md` § 色は変数の名前で書く と同じ決まりで、同じ理由による。
