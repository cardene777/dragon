# 箱が行を持つ図 (`type: record`)

畳む前の `er` / `state` とクラス図の意匠帳は `../er/note.md` と `../class/note.md` に残っている。
あちらは **決めた日の記録** で、この file が今の記法を持つ。

## 何を 1 つにしたか

`type: er` と `type: state` を `type: record` に畳み ([#2782](https://github.com/cardene777/dragon/issues/2782))、
`type: class` も同じ一つの型へ畳んだ ([#2783](https://github.com/cardene777/dragon/issues/2783))。

2 つは描画側へ渡す形がほぼ同じだった。
箱はどちらも表の箱 (`storage`)、行頭の印はどちらも 形 (四角 / 山形) × 塗り (塗る / 中空) の 2 軸、行の帯もどちらも同じ。
違うのはその 2 軸を何と呼ぶかだけだった。

記法の層では `er` と `class` の説明文が同じ文字列にすらなっていた。

### 畳んだ根拠

名前が 2 つあることで、同じ扱いをしたい場所が分岐に割れていた。
`packages/dragon/src/compile.ts` に `doc.type === "er"` 等の分岐が 13 か所あり、縦列の設定表と図種の作りの表にも同じ値の行が並んでいた。
分岐を 1 か所書き忘れると黙って外れる。

実際に `type: er` へ `lanes:` を足すと箱の種類が人の形に変わり、行の帯が消える不具合が残っていた。

同じ畳み方は数を描く図で 1 度通っている。
形ごとに 9 つの型を持っていたのを `chart` と `shape:` の組に畳んだ時の決まりが「読み替えは読み取りの入口 1 か所に閉じる」 で、この回も同じ形を採った。

## 行頭の印は 3 語

描画側が持つ印は 3 軸しかない。
形と塗りと名前の下線で、この 3 軸に 1 対 1 で当たる語を dragon 自身が持つ。

| 語 | 軸 | 意味 |
|---|---|---|
| `鍵` | 名前に下線を引く | その行で箱を見分ける |
| `外` | 行頭を山形にする | その行は箱の外とつながる |
| `条件` | 行頭を中空にする | その行は条件が揃った時だけ効く |

語を 1 つも書かない行は 四角 + 塗る + 下線なしで、箱の中で完結して常に在る行になる。
1 行に 2 つ以上書ける (`鍵 外` の形)。

### 古い語は入口で読み替える

畳む前の 2 つの語彙は、同じ 2 軸の格子を別の名前で呼んでいただけだった。
格子の 4 隅は 1 対 1 に重なる。

|  | 塗る | 中空 |
|---|---|---|
| 四角 | 語なし / `do` | `条件` / `opt` / `internal` |
| 山形 | `外` / `fk` / `entry` | `外 条件` / `fk opt` / `exit` |

読み替えは `packages/dragon/src/compile/row-marks.ts` の `行頭の語の別名` が持つ。
読み取りの入口は 3 経路 (縦に並べた形 / 中括弧の形 / JSON) あり、3 つとも同じ関数を通す。
ここを通った後は古い語がどこにも残らないので、組み立て側は 3 語だけを扱う。

図種の名前 (`er` / `state`) は綴りごと消したが、行頭の語は残した。
名前を無くすのが目的の図種と違い、語が指す印は 1 つに決まっており、`pk` と `鍵` は同じ絵になる。

### `鍵` を書いた行は上にまとめる

畳む前の表の図が同じ並べ替えをしていた (組み立て器 `er()` と同じ形)。
`鍵` を 1 つも書かない図では並びが 1 行も動かない。

空の行では群を分けない。
群の区切りは行頭の印が持っており、空の行を挟むと行の間隔が不揃いになる。

### クラス図の群も行頭の印で書く

クラス図の振る舞いは `外`、非公開は `条件` で書く。したがって、旧クラス図の
`+name / -secret / ─── / +login() / -hash()` は、record の
`"" / 条件 / 外 / 外 条件` と行頭の印の形・塗り・並びが一致する。

群分けを行頭の印とは別の独立した欄にする案は取り下げた。同じ見た目を既存の3軸で表せるのに
4つ目の軸を足すと、同じ情報を二度持ち、食い違う余地が増えるため。`docs/design/record/note.md` が
すでに退けた空の行による区切りも持ち込まない。

## 書かないものを図が名乗らない

畳む前は、書かれていない値を図種の名前から推し量る既定が 4 つあった。
どれも落とした。

| 畳む前 | 畳んだ後 | 落とした理由 |
|---|---|---|
| 1 つも書かない図は並びの最初と最後を始まりと終わりとみなす | 書いた箱にだけ札が付く | 行を並べた表の箱に「初期」 の字が出る |
| 始まりでも終わりでもない箱に「状態」 の札を配る | 何も付けない | 図種の名前をそのまま字にしていた |
| 移り変わりの矢印に「実線に開いた矢」 を無条件で渡す | 書いた端だけが届く | 多重度から導いた端 (鳥の足や棒) を上から潰す |
| 表の図は書かなくても生成りに茶 (`kinari`) になる | 書いた図だけが色みを持つ | 移り変わりの図が書いていない色みを名乗る |

3 つ目の代わりに見本帳の側を固定した。
行を持つ図の矢印はすべて端を書く (`packages/dragon/test/record-edge-head.test.ts` が 1 本ずつ名指しする)。

4 つ目も見本帳の側で書く。
表を描いた見本 4 件に `palette: kinari` を足した。

### 配色だけは中身から決められない

他の 3 つは書いた中身から決め直せたが、配色はできない。

表の図と移り変わりの図は、行の有無でも行の中身でも分かれない。
どちらも `kind: storage` の箱に `督促を送る: 7 日ごと` の形の行を書くため、
`:` で名前と型に分かれるかを見ても分かれない。

印 (`鍵`) を材料にする案は試して退けた。
印を書かずに行の本文で書く形 (`id: PK`) があり、表の図 1 枚が縞を落とした。

行の有無を材料にする案も退けた。
移り変わりの箱が動きの行 (`在庫を押さえる`) を持つため、移り変わりの図が色みを名乗る。

縞は配色からしか色を取らないので、配色が決まった図の行を書いた箱にだけ敷く。
クラス図も record に畳んだため既定は残さない。クラス図の見本は `palette: kinari` を明記する。

## UML の関係

`relation` を書いた record は、継承 / 実装 / 集約 / コンポジション / 関連 / 依存の
線種・両端の形・塗り・3群の色を `classDiagram` と同じ表から受け取る。

`sub` は `relation` の有無で意味を分ける。`relation` がある時は行き先側の多重度 (`headLabel`)、
無い時は従来どおり線の名前の下の補足。`tailSub` は出どころ側 (`tailLabel`) に置く。
この境界なら、旧 class の多重度を同じ欄のまま移せ、既存 record の補足も壊さない。

画面の細い関係線は、`record` 全体には当てない。record は UML / 表 / 移り変わりを一つに
畳んでおり、図種だけでは線の意味を分けられないため。#2805 と同じく端の印で囲い、個数の
`one` / `many` / `zero-one` / `zero-many` に加えて、UML の中抜きの三角 (`triangle` + `hollow`) と菱
(`diamond` + 任意の塗り) を持つ図へ当てる。端を書かない線の既定の矢じりは、同じ三角でも
塗りが `solid` なので継承 / 実装と分かれる。これで書き直したクラス図は細く、`認証の状態遷移` は
矢じりを書かないまま元の濃さになる。

`associates` (関連) と `uses` (依存) は、どちらも移り変わりと同じ `open` しか描いた SVG に
持たない。線種や色みも利用者が上書きでき、UML だけを示す既存属性は無いので、端だけでは
単独の関連 / 依存の図を見分けられない。`open` を囲うと移り変わりまで細くなるため対象外にする。
見本帳の UML クラス図は継承と所有の端も持つので、図全体として `triangle` / `diamond` により
囲われ、6 種すべての線が同じ細さになる。識別専用の新しい属性はこの判断だけのためには足さない。

## 書かなかった時に content から決めるもの

図種では決められなくなった分を、書いた中身から決める。

| 何を | 決め方 |
|---|---|
| 箱の形 | 行を書いた箱は表の箱 (`storage`)、書かない箱は札 (`card`) |
| 縦列の幅 | 行を持つ箱が 1 つでもあれば 450、無ければ 360 |
| 前へ戻る矢印を回すか | 縦列を書いていない図でだけ回す |

3 つ目は、回すのが「書いた順に並ぶから戻る線が箱を貫く」 ための手当てだから。
縦列と段を書いた図は書いた人が置き場所を決めているので回さない。
回し始めると線が往復して戻る弧になり、関係の無い箱を貫いた (実測 = `利用者 -> 会員証` が同じ点へ 2 度戻る形になった)。

## 組み立ての経路は 1 本

畳む前は図ごとに 2 経路あり、`animate:` も `lanes:` も書かない図だけが組み立て器 (`er()` / `stateMachine()`) に落ちていた。
その経路は書いた行を捨てており (`rows: []` を渡していた)、記法に行を書いても図に出なかった。

動きを 1 段足すだけで行が現れる形になっていたので、同じ記法が同じ図になるほうへ倒した。

経路が 1 本になったことで、図 1 枚ごとに読むかが決まる箱の欄も無くなった。
