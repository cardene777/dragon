# 設計 file

## `app.pen`

画面 9 種の構成を描いた設計 file。 Pencil で開く。
画面は明るい側の 1 枚ずつだけを描き、 暗い側の frame は持たない。

受け持つのは **画面の節の構成** で、 実装との突き合わせは
`apps/playground-spa/tests/design-structure-matches.spec.ts` が見る。

**サイトの配色の元ではない**。 配色は実装 (`apps/playground-spa/src/styles/globals.css`) が持ち、
`.pen` の色と突き合わせる検査も無い。

`.pen` の中の配色は色変数に集約してあり、 図の側はその変数を参照する。 直書きで残るのは透明だけなので、
**変数を直せば図全体に届く**。 変数は設計の図を描くための値で、 明暗の 2 値は持たない。

変数がいくつあるか、 どれだけの箇所が参照しているかは `.pen` を JSON として読んで数える。
ここに数を書き写すと、 変数を 1 つ足した日から古くなる。

中身は素の UTF-8 JSON で、 `JSON.parse` がそのまま通る。 検査もこれを直接読む。

`.pen` を Pencil で編集した後は **保存 (Cmd+S) が要る**。 MCP の `execute` は editor 上の
状態を変えるだけで、 disk には書かない。

### 配色を変える時

実装の `globals.css` だけを直す。 `.pen` は合わせなくてよい。

## 配色を突き合わせなくなった経緯 (#2973)

`.pen` と `globals.css` の配色は、 以前は検査で突き合わせていた (#1124)。
実装だけを動かして 14 箇所ずれていたのを `.pen` を追随させて揃え、 以後のずれを検知するためだった。

サイトの見た目は意匠ごとの値の表で決める形に替わり (#2962)、 明暗の切り替えは無くなる。
突き合わせる相手の `html.dark` が消えるので、 検査と暗い側の frame を外し、 `.pen` を配色の元から外した。
