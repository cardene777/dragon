# dragon サイト 画面一覧

dragon の公開サイトを、 明るい画面と暗い画面の 2 つだけで作り直すための画面一覧。

今ある見た目の主題 6 種は畳む前提のため、 ここには書かない。

## 描く範囲

公開されている 9 画面すべてを、 明るい画面と暗い画面の 2 状態で描く。

開発時にしか出ない検査用の頁 (`/__render`) は対象外。

| # | 画面 | 経路 |
|---|---|---|
| 1 | トップ | `/` |
| 2 | カタログ一覧 | `/catalog` |
| 3 | カタログの分類 | `/catalog/:slug` |
| 4 | エディタ | `/editor` |
| 5 | ドキュメント | `/docs` |
| 6 | 見本の詳細 | `/preset/:id` |
| 7 | 更新履歴 | `/release-notes` |
| 8 | 参加方法 | `/contribute` |
| 9 | 見つからない頁 | 上記以外すべて |

## この製品が何か

文章で図を書く道具。

登場人物と流れを箇条書きで 1 行ずつ並べると、 時間を持つ図が立ち上がる。

止まった絵では伝わらない順序と因果を、 動きで伝えることが目的。

図は `SVG` として画面に描かれ、 局面 (`phase`) ごとに切り替わって動く。

## 全画面に共通する上部の帯

すべての画面の最上部に同じ帯が乗る。

| 位置 | 中身 |
|---|---|
| 左 | 印 + 名前 `dragon` + 添え書き `— animated diagram dsl` |
| 中央 | 行き先 6 つ = トップ / カタログ / エディタ / ドキュメント / リリースノート / `GitHub ↗` |
| 右 | 言語の切替 / 明暗の切替 / この頁を共有 / `エディタを開く →` |

今いる画面に当たる行き先には、 現在地だと分かる印を付ける。

`エディタを開く →` は帯の中で最も強い呼びかけとして扱う。

## 1. トップ (`/`)

最初に来た人に、 何ができる道具かを見せて `エディタ` へ送り出す画面。

縦に 5 つの区画を積む。

### 1-1. 呼びかけ

小さな前置きとして `v0.7` と `49 種の形 × 時間軸 × 絶対配置` を並べる。

見出しは「より自由な図を」 で、 「図」 だけ強調する。

**読点で割らない**。 日本語の見出しを英語の comma のように割ると主張が 2 つに散る。

説明文は「形を選び置き場所を決め局面ごとに動かす。 型に合わせて諦めていた図が、 文章のまま組み上がる。」

呼びかけの釦を 2 つ置く。 強い方が `エディタを開く →`、 弱い方が `ドキュメントを読む`。

### 1-2. 実物の見本

窓のような枠を 1 つ置き、 左に書いた文、 右に出来上がった図を並べる。

枠の上辺に、 丸 3 つ + 書類名 `api-call.dragon` + 進行中の局面 `phase 2 / 4 · API → DB` を置く。

左は 19 行の箇条書きで、 表題 / 種類 / 登場人物 3 名 / やりとり 4 本 / 動きの指定 4 つが読める。

右は登場人物 3 名 (`User` / `API` / `DB`) の縦線と、 その間を渡る矢印 4 本の図。

矢印には `POST /login` / `SELECT user` / `row (1)` / `200 OK` の札が付く。

### 1-3. 特長 3 つ

区画の見出しは前置きが「なぜ dragon か」、 本文が「書く手間を、 動く成果に。」

| 見出し | 説明 |
|---|---|
| `YAML` 風で書ける | 登場人物と流れを箇条書きで宣言するだけ。 図の内部構造を組む必要はない。 |
| (2 つ目) | 図が動く仕組みに関する特長 |
| (3 つ目) | 図の共有と持ち出しに関する特長 |

3 つとも、 印 + 見出し + 2 行程度の説明という同じ形にする。

### 1-4. 3 手順

区画の見出しは前置きが `3 steps`、 本文が「1 分で走り出す。」

| 番号 | 見出し | 説明 |
|---|---|---|
| 1 | エディタを開く | ブラウザで `/editor` にアクセス。 導入作業は要らない。 |
| 2 | `YAML` を書く | 登場人物と流れを箇条書きで宣言する。 `type: sequence` で図の種類を選ぶ。 6 行程度の抜粋を添える。 |
| 3 | `SVG` が動き出す | 右の実況表示に局面ごとに動く図が出る。 場所を指す文字列で共有もでき、 持ち出しもできる。 |

2 つ目にだけ、 実際の記述の抜粋が入る。

### 1-5. 用例 3 つ

区画の見出しは前置きが `use case`、 本文が「こんな図が書ける。」

札を 3 枚横に並べ、 1 枚につき図の縮小版 + 種類の名札 + 見出し + 説明を入れる。

| 種類 | 見出し | 説明 |
|---|---|---|
| `sequence` | `API` 呼び出しの流れ | 登場人物どうしのやりとりを時間軸で並べる。 認証や `API` 連携の説明に。 |
| `topology` | システム構成図 | 部品の配置と、 要求がどこを通るかを同時に描く。 |
| `er` | データベースの構造 | 実体と関係を順番に見せる。 構造の見直しや引き継ぎに。 |

3 枚の下に `図のカタログを見る →` を置く。

### 1-6. 最後の呼びかけ

見出しは「今すぐ、 書いて動かす。」

説明は「`YAML` を 1 つ書くだけ。 動く図を 1 分後に手に入れる。」

釦は `エディタを開く →` と `GitHub ↗` の 2 つ。

## 2. カタログ一覧 (`/catalog`)

書ける図を分類ごとに見渡して、 目的の分類へ送り出す画面。

上部に道筋 (`概要 › カタログ`) と見出し `カタログ` と説明を置く。

その下に分類の札を 10 枚並べる。 1 枚につき見出し + 3 行程度の説明 + `開く →`。

| 分類 | 何が置かれているか |
|---|---|
| プリセット | 種類が決まっている時の最短経路。 1 行で骨格ができる。 |
| レシピ集 | 現場でよく議論される要件をそのまま図にした集合。 |
| パターン | 図の組立てで繰り返し出る汎用の型。 直結か分岐か繰り返しかを先に選ぶ。 |
| 基本要素 | 最小の構成要素 5 種と、 分野ごとの節点の種類。 |
| テキスト `DSL` | 箇条書きだけで図を書く経路。 5 つの塊で済む。 |
| アニメーション | 動く図の書き方。 局面での推移 / 数値の補間 / 即時の切替 / 名札での局面表示。 |
| イーサリアム | 残高が付け替わる、 手数料が上下する等の変化そのものを見せる図。 |
| パーツ | 小部品の見本市。 入れ物 / 計器 / 指標 / 時系列など。 |
| スタイル | 実線と点線、 6 系統の色味で図の中に意味の階層を差し込む。 |
| インタラクティブ | つまみを動かす、 巻き取りで局面が進む、 押して切り替わる等の仕組み。 |

10 枚は同じ形と大きさで、 説明の長さの違いで崩れないようにする。

## 3. カタログの分類 (`/catalog/:slug`)

1 つの分類に属する図を、 実物と記述の対で並べる画面。

道筋は `概要 › カタログ › <分類名>`。

見出しと説明の下に、 図の項目を縦に積む。 1 項目は上から順に次の 4 つ。

1. 項目名と、 何を示す図かの短い説明
2. 図の実物 (動く。 局面が進む間、 進行度が分かる表示が付く)
3. 記述の切替 (`yaml` と `json` の 2 択) と `コードをコピー` の釦
4. 選ばれている方の記述本文

図が並ぶ画面なので、 図の背景と頁の背景の関係が最も問われる。

図を大きく見るための重ね窓も持つ。 開くと画面全体を覆い、 図 1 つだけを大きく出す。

## 4. エディタ (`/editor`)

この製品の中心。 書いた文がすぐ図になる作業場。

上部の帯の下を、 左から順に 3 つの縦の領域に割る。

### 4-1. 左の棚

新規作成の釦を最上部に置く。

その下に見本と部品を切り替える 2 つの見出しがあり、 選ばれた方の一覧が下に出る。

一覧の上に絞り込みの入力欄。 一覧は分類ごとの小見出しで区切る。

### 4-2. 中央の記述欄

上辺に、 記述の種類の切替 3 つ (`cdl` / `yaml` / `json`) と書類名と持ち出しの釦を並べる。

本体は行番号付きの記述欄。

記述欄の下に、 3 種類の知らせが出る領域を持つ。

| 種類 | 見え方 |
|---|---|
| 誤り | 読めなかった箇所を、 記述と同じ等幅の字で示す |
| 気付き | 行番号 + 本文 + 補足の 3 つを 1 行に並べる |
| 助言 | 件数の名札 + 一括で直す釦 + 観点と詳細を並べた一覧 |

助言の一覧には、 何の観点かを示す短い名札が各行の先頭に付く。

### 4-3. 右の実況表示

書いた内容から起こした図を、 動いた状態で出し続ける領域。

拡大縮小と再生の操作を持つ。

3 領域の境目は、 どこまでが記述でどこからが結果かが一目で分かる形にする。

#### 方眼

**既定では出さない**。 掴んで動かす時の目安が要る人だけ、 操作で出せるようにする。

出す時は罫 (線) ではなく **24px 刻みの点** で描く。 図の中身も線 (生存線 / 矢印) なので、
罫だと同じ種類のものが画面全体に敷き詰められて図と競合する。

方眼の有無で舞台の色は変えない。 1 つの操作が 2 つのことをすることになるため。

出した姿は `04b エディタ 点の方眼` に描く。

## 5. ドキュメント (`/docs`)

読み物の画面。

上部に前置きと見出しと説明、 呼びかけの釦 2 つ (`エディタ` へ / `カタログ` へ) を置く。

その下に特長の札を並べ、 さらに下に長い本文が続く。

本文の節は次の 7 つ。

| 節 |
|---|
| 5 分で動かす |
| 30 秒で雰囲気を掴む |
| 5 つの基本要素 |
| 6 種類の高位 `API` |
| 9 実用例 |
| `Mermaid` から移行 |
| 「目」 が検証する |

本文には記述の抜粋と、 図の実物と、 表が混ざる。

長文を読み続けられることが、 この画面で最も大事な性質。

## 6. 見本の詳細 (`/preset/:id`)

見本 1 件だけを大きく見せる画面。

道筋は `概要 › カタログ › プリセット`。

図を大きく置き、 その下か横に記述を置く。

操作は `エディタで開く` と `URL コピー` の 2 つ。

前後の見本へ移る `前へ` と `次へ` を持ち、 左右の鍵でも移れる。

`URL コピー` を押した時に、 成否を伝える小さな知らせが浮く。 成功と失敗の 2 通りが要る。

## 7. 更新履歴 (`/release-notes`)

版ごとの変更を伝える画面。

道筋は `概要 › リリースノート`。

上部に見出し `リリースノート` と説明、 外部へ出る釦 2 つ (`CHANGELOG を GitHub で見る` / `GitHub リリース一覧`)。

その下に最新版の要約を置く。 版の名前 (`v0.5 (最新)`) と、 主な数値の札を横に並べる。

さらに下に版ごとの記録が続き、 各版に `GitHub で読む` が付く。

## 8. 参加方法 (`/contribute`)

外から手を入れたい人に、 入口を示す画面。

道筋は `概要 › コントリビュート`。

上部に見出し `dragon にコントリビュートする` と説明、 外部へ出る釦 2 つ (`CONTRIBUTING.md を読む` / `Issue を起票`)。

その下に手段の札を 3 枚並べる。

| 見出し | 行き先 |
|---|---|
| バグ報告 | `バグを起票` |
| 機能提案 | `機能を提案` |
| `Pull Request` | 手順の説明 |

### 8-1. `PR` を出すまでの 5 手順

手段の札の下に、 手を動かす人向けの手順を 5 段並べる。

3 経路のうち `PR` だけが手を動かす経路なので、 枝を切ってから出すまでを順に置く。

| 手順 | 中身 |
|---|---|
| `branch` を切る | 枝の名前は `feature/<番号>-<短い説明>` で揃える。 |
| `test` を先に書く | 動作証明のない記述は取り込みの対象外。 1 つの `PR` で 1 つの話題に絞る。 |
| 検査を通す | 型の検査と `test` がどちらも通ること。 組み立ても緑にする。 |
| 説明文を書く | 何を変えたか、 なぜそうしたかを分けて書く。 起票番号を必ず結ぶ。 |
| 出す | 下書きで出しても構わない。 迷った時点で相談してほしい。 |

## 9. 見つからない頁

大きな番号 `404` を置く。

見出しは「そこは、 まだ書かれていない。」

説明は「お探しの頁は移動または削除されたか、 そもそも存在しません。 dragon の 4 つの入口から探してみてください。」

行き先の釦を 3 つ横に並べる (`エディタ` / `カタログ` / `ドキュメント`)。

この画面だけは中身が薄いので、 余白の取り方だけで成立させる。

## 明暗の 2 状態について

9 画面すべてに、 明るい状態と暗い状態の 2 つを作る。

同じ骨格のまま、 どちらでも読めることが条件。

とくに次の 3 箇所は、 明暗のどちらでも成立している必要がある。

| 箇所 | 要求 |
|---|---|
| 図が置かれる領域 | 図の線と文字が、 頁の地の上で読める |
| 記述欄 | 行番号と本文と強調が、 長時間見て疲れない |
| 知らせの 3 種類 | 誤り / 気付き / 助言 が互いに見分けられる |

図の中で使う色は、 画面の色と同じ体系から取る。

図だけ別の体系にしない。
