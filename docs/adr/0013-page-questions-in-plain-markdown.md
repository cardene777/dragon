# 説明の頁の答えと確かめる問いと用語を、GitHubが読める標準のMarkdownで書く

## 決めたこと

`dragon export`で書き出すMarkdownの頁に、説明の頁の組み立て`layout: guide`を足す。
`layout: guide`の頁は、`##`が話題のタブ、`###`がそのタブの中に縦に積む問いの節になる。
`entry`、`sidebar`、`tabs`の3つの組み立ては今のまま変えない。
問いの一覧、1文の答え、確かめる問い、用語の札は、新しい記号を足さず、GitHubがそのまま読める標準のMarkdownの形を読み替える。

| 書く形 | 頁での見え方 |
|---|---|
| タブ (`##`) の中の節の題 (`###`) | タブの頭の「このタブで答える問い」の一覧。押すとその節へ移る |
| 節の題の直後の引用 (`>`) | 1文の答え |
| `<details>`と`<summary>` | 確かめる問い。答えは押すまで隠す |
| 用語の場所へのリンク (`[用語](glossary.md#用語)`) | 下線と、押すと出る用語の札 |

用語の説明は用語だけの別のfile (`glossary.md`) に書く。
`###`の見出しが用語、続く段落が説明、その後の引用が例になる。
頁では`![用語](glossary.md)`の行で読み込み、「用語」のタブにもする。
1つの用語の説明は頁で1か所にだけ書き、同じ用語を2か所に書いた時は書き出しを断る。
印刷とPDFでは、用語の札と箱の札と確かめる問いの答えを全て開いた、動きの無い形にする。

## 選んだ案

書き手は新しい決まりを覚えずに済み、書き出す前のMarkdownをGitHubで開いても、引用と用語へのリンクと開閉できる問いとして崩れずに読める。
用語の説明を別のfileに置くと、本文のfileが短く保たれ、全ての説明を1つのfileで見直せ、他の頁でも使い回せる。
読み手は札で説明を読むので、書く場所が本文から離れても困らない。

## 却下した案とその理由

| 案 | 却下した理由 |
|---|---|
| `layout: tabs`の`###`を、項目のタブでなく縦に積む節に替える | `tabs`で書いた今の頁の形が変わる |
| 題の直後に答えの引用を持つ`###`だけを縦に積む節にする | 1つの頁の中で`###`の見え方が2通りになる |
| `[[用語]]`と`??`のdragonの短い記法で書く | GitHubでは`[[ ]]`と`??`が字のまま出て崩れる |
| 答えと問いを`answer`と`quiz`の囲みで書く | GitHubではコードの囲みとして出て、答えと問いに見えない |
| 用語の説明を同じfileの最後の`## 用語`の節に書く | 本文のfileが長くなる |
| 用語の説明を初めて使う節の終わりに書く | 用語が頁の中に散らばり、1か所で見直せない |
