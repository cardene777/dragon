# c4 preset

The `c4` preset expresses the system context layer of the C4 model (a four-layer approach: Context / Container / Component / Code).
It maps to mermaid `C4Context`, distinguishing person / system / external system through existing NodeKinds (`person` / `service` / `api` / `database` / `cdn`, etc.).

## When to use

- Show the overall system context (users / our system / external systems) on a single page.
- Visualize DDD bounded context boundaries.
- Combine with AWS / Azure deployment diagrams.

It currently borrows the topology preset's group layout; express boundaries via top-level `lanes` / `groups` with `contain: true`.
A full C4 implementation (Container / Component diagrams, boundary frames) is planned for a future PR.

## Minimal example

::: tabs

@@@ humans 👤 For humans

```text
title: "System Context"
type: c4

actors:
  - User: { kind: person, subtitle: "End user" }
  - Web: { kind: service, subtitle: "Frontend" }
  - API: { kind: api, subtitle: "Backend" }
  - DB: { kind: database, subtitle: "PostgreSQL" }

flow:
  - User -> Web: "uses"
  - Web -> API: "calls"
  - API -> DB: "reads"
```

@@@ llm 🤖 For LLM

```yaml
preset: c4
intent: "C4 model system context diagram"
actors:
  - { id: User, kind: person, role: end-user }
  - { id: Web, kind: service, role: frontend }
  - { id: API, kind: api, role: backend }
  - { id: DB, kind: database, role: persistence }
flow:
  - { from: User, to: Web, label: uses }
  - { from: Web, to: API, label: calls }
  - { from: API, to: DB, label: reads }
constraints:
  - "person = user, service / api = our system, cdn / external = external system"
  - "boundary expression via top-level lanes / groups with contain: true"
  - "only C4 context is supported today, Container / Component is future work"
```
